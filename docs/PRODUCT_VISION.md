# Mesh.me Product Vision

Motto: Your World, Your Way

Mesh.me is a privacy-first, security-focused social media platform and digital identity hub. It is both a standalone social network and a universal control center for a user's connected online life.

The product goal is to let users see, manage, understand, and interact with their digital footprint from one place: posts, comments, likes, followers, messages, synced content, platform permissions, analytics, privacy, and identity.

## Product Principles

- User control is the default. Users should understand what is stored, synced, visible, deleted, exported, or shared.
- Privacy and security are core product requirements, not optional settings.
- Mesh.me does not rely on ads, manipulative ranking, or hidden data resale.
- Third-party content must preserve source attribution and, where APIs permit, sync engagement back to the original platform.
- The same underlying data should support multiple interfaces: the Mesh, Feed, MeChat, and Analytics.
- AI should be concentrated in Meshi. Generic scattered AI features should be avoided.

## Core Product Areas

### The Mesh

The Mesh is the primary identity and navigation layer. It should represent a user's digital world as a live graph of people, posts, platforms, communities, interests, messages, interactions, and permissions.

The Mesh must be backed by explicit graph concepts: nodes, edges, sources, visibility, sync state, ownership, and interaction history.

### Feed

The Feed is the familiar scroll-based interface over the same unified content model that powers the Mesh. It exists to make Mesh.me immediately usable for people who do not want to start with a graph interface.

Feed modes should eventually adapt to user preference, such as compact social feed, media-first feed, creator dashboard, or simplified Facebook-like layout.

### MeChat

MeChat is the communication layer. It should unify native Mesh.me messaging with supported cross-platform messages and share activity.

Long term, MeChat should support group browsing sessions where users can browse together while each participant still acts as themselves.

### Analytics

Analytics is both insight and control center. It should show performance, growth, engagement, sync status, permissions, data inventory, privacy state, export controls, and deletion controls.

Analytics is where transparency becomes concrete.

### Meshi

Meshi is the user's minimal character identity inside the Mesh and the platform's only deeply integrated AI companion.

Meshi should be simple: bubbly body, two eyes, no mouth, minimal accessories, and strong customization without visual clutter.

Meshi should be powered by an LLM so it can answer broad user questions, not only predefined product FAQs.

Meshi should understand natural language commands and execute user-approved actions on the user's behalf across mesh.me workflows (for example posting, messaging, navigation, and account operations), with clear confirmation and auditability.

Meshi AI should still prioritize privacy, minimize cloud dependence where practical, and avoid unnecessary data retention.

## Trust Requirements

The following are non-negotiable for the product direction:

- Centralized privacy policy enforcement across profile, feed, mesh, search, and API routes.
- Encryption at rest for third-party OAuth tokens.
- Strong account protection, including real two-factor authentication before it is marketed as enabled.
- Clear permission and sync controls per connected platform.
- Data export and deletion controls.
- Auditability for sensitive data and sync operations.
- Source attribution for imported content.

## Monetization

Mesh Pro is the monetization model. It should add optional value without degrading the free experience.

Appropriate Mesh Pro areas include deeper analytics, additional Meshi customization, Mesh visual customization, interface personalization, and creator-grade management tools.

Mesh.me should not use ads or hidden data resale as a business model.
